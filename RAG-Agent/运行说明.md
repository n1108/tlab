# RAG-Agent 运行说明

本文说明如何安装依赖、配置大模型 API，以及如何运行 **RAG-Agent**（工具调用 + 多轮推理；失败时回退为与 `exp` 一致的单跳 Judge）。

---

## 1. 环境准备

- Python **3.10+**
- 本机已具备与 `exp` 相同的数据：在 `dataset` 目录下有 `input.json`，以及按日期组织的 `metric-parquet`、`trace-parquet`、`log-parquet`（路径规则与 `MetricAgent` / `TraceAgent` / `LogAgent` 一致）。

进入 `RAG-Agent` 目录，安装依赖：

```bash
cd RAG-Agent
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

也可使用可编辑安装（便于改代码）：

```bash
pip install -e .
```

安装后可直接使用命令（若已配置 `pyproject` 里的 `rag-agent` 入口）：

```bash
rag-agent --help
```

若未用 `pip install -e .`，需用 **`PYTHONPATH` 指向 `RAG-Agent` 根目录**（见下文）。

---

## 2. 大模型 API 配置

RAG-Agent 默认使用 **Yuzo**：

- **Yuzo（默认）**：设置环境变量  
  `YUZO_API_KEY`  
  可选：`YUZO_API_URL`（若使用自定义网关）
- 若要切换到其他 OpenAI 兼容服务，可传 `--llm-provider` / `--llm-model` / `--llm-api-url`

也可在命令行临时传入（不推荐写入脚本入库）：

```bash
--llm-api-key "你的key"
--llm-api-url "https://..."
```

未配置有效 API Key 时，程序会在启动时报错并退出。

---

## 3. 如何运行

### 3.1 在 `RAG-Agent` 目录内运行（推荐）

假设数据集在上级仓库的 `dataset` 文件夹（与当前 tlab 布局一致）：

```bash
cd RAG-Agent
source .venv/bin/activate
export YUZO_API_KEY=你的密钥

PYTHONPATH=. python3 -m rag_agent \
  --dataset-root ../dataset \
  --limit 1 \
  --max-workers 4
```

- `--dataset-root`：数据根目录，需包含 `input.json` 及 parquet 数据。
- `--limit 1`：只跑前 1 条用例（调试常用）；去掉则跑完全部。

### 3.2 在仓库根目录（tlab）运行

```bash
cd /path/to/tlab
export YUZO_API_KEY=你的密钥

PYTHONPATH=RAG-Agent python3 -m rag_agent --limit 1 --max-workers 4
```

此时默认 `--dataset-root` 会解析为 **`tlab/dataset`**（即 `RAG-Agent` 的上一级目录下的 `dataset`）。

### 3.3 只跑指定 UUID

```bash
PYTHONPATH=. python3 -m rag_agent \
  --dataset-root ../dataset \
  --uuid 345fbe93-80
```

### 3.4 常用参数说明

| 参数 | 说明 |
|------|------|
| `--dataset-root` | 数据集目录，默认尝试 `../dataset`（相对 RAG-Agent）或从 tlab 根运行时指向 `dataset` |
| `--input` | 自定义 `input.json` 路径，默认 `<dataset-root>/input.json` |
| `--output` | 输出 JSONL 路径，默认 `RAG-Agent/output/rag_agent_run.jsonl` |
| `--uuid` | 只处理该 UUID |
| `--limit N` | 最多处理 N 条（与 `--uuid` 二选一逻辑：先过滤 uuid 再 limit） |
| `--max-turns` | 工具多轮对话最大轮数，默认 `8` |
| `--max-workers` | case 并行 worker 数，默认 `4` |
| `--log-level` | 日志级别，默认 `INFO` |
| `--llm-provider` | 默认 `yuzo` |
| `--llm-model` | 指定模型名（可选） |

---

## 4. 输出说明

- **结果文件**：默认 `RAG-Agent/output/rag_agent_run.jsonl`，每行一个 JSON，字段与评测用答案类似：`uuid`、`component`、`reason`、`reasoning_trace`，并额外包含 **`rag_meta`**：
  - `mode`：`rag_tools` 表示走通了工具提交；`fallback_judge_analyze` 表示在达到最大轮数等情况下回退为单次 `JudgeAgent.analyze`。
- **日志文件**：默认 `RAG-Agent/output/rag_agent.log`。

---

## 5. 常见问题

1. **`ModuleNotFoundError: No module named 'openai'`**  
   执行 `pip install -r requirements.txt`。

2. **`No LLM API key`**  
   设置 `YUZO_API_KEY` 或使用 `--llm-api-key`。

3. **`input.json not found`**  
   检查 `--dataset-root` 是否指向包含 `input.json` 的目录。

4. **接口不支持 `tools`**  
   模型可能无法按 OpenAI 格式调用工具；多轮结束后会自动走 **fallback 单跳 Judge**，仍能得到一条结果，但 `rag_meta.mode` 会是 `fallback_judge_analyze`。

5. **数据路径**  
   RAG-Agent 代码不引用仓库其它 Python 包，但 **必须**能通过 `--dataset-root` 读到真实 parquet；布局需与现有 `exp` 一致。

---

## 6. 与 `exp/main.py` 的关系

- **检测逻辑**：与 `exp` 中 `MetricAgent` / `TraceAgent` / `LogAgent` 一致（已拷贝在 `rag_agent/bundled/`）。
- **差异**：本工程优先让大模型通过 **function calling** 按需拉取三类证据，最后 `submit_root_cause_analysis`；若未完成则与 `exp/main` 一样调用 **`JudgeAgent.analyze`** 一次性融合。

## 7. 速度优化说明

- 默认已开启 **case 并行**（`--max-workers=4`）。
- 默认已开启 **单 case 工具预取并行**（环境变量 `RAG_PREFETCH_TOOLS=1`，无需额外设置）。
- 如想排查速度问题，可临时关闭预取：

```bash
RAG_PREFETCH_TOOLS=0 PYTHONPATH=. python3 -m rag_agent --dataset-root ../dataset --limit 1
```

如需对照评分，可将生成的 JSONL 与 `dataset/groundtruth.jsonl` 用现有 `dataset/评分.py` 对比（注意输出路径与字段格式需与评测脚本一致）。
